# Assignment compliance review — 15 November 2026

This review uses the seven-page `Assignment_03_MLOps_AI_Agent_Complete.pdf` as the acceptance
criteria. Existing working adapters, training code, DAG and inference API were retained.
Original exports under `docs/evidence/` describe 10 November. New checks are collected under

## Changes made

* Hardened Ollama planning: configured experiment/DAG/scope in the prompt, feedback for missing
  mandatory evidence, exact provenance correlation, duplicate-call suppression, 12 turns/24
  proposals/600-second deadline, and serving-model/token-count traces. No rules fallback is
  performed in LLM mode. Full tool results remain available outside bounded model excerpts.
  Invalid calls or premature prose activate supported Ollama JSON-schema action selection;
  original executor validation remains authoritative. Grammar patterns use explicit ASCII ranges.
  Provenance lookup choices are grounded to the selected run's actual commit/pointer; recovery
  context retains tool results rather than repeating obsolete model arguments or prose.
* Added protocol tests for multi-turn four-domain reasoning, premature answers, repeated writes,
  forged confirmations, unknown tools, unavailable tools, malformed LLM responses, timeouts,
  hallucinated final prose and large logs. Added a regression for unrelated DVC provenance.
* Classified Kubernetes SDK timeouts correctly and redacted JSON-formatted credentials and bare
  JWTs in diagnostic log strings. Existing exact-action authorization and namespace/RBAC remain.
* Added a submission-file and reachable-history credential audit and CI enforcement.
  Runtime state and credentials stay local and ignored. Submission uses the repository link.
* Added repeatable local/live verification commands, planner/output selection in the demo,
  mandatory-scenario assertions, and a normal recovery DAG after deliberate failures.
* Strengthened offline manifest/DAG checks to verify namespace, Service selectors, retries, and
  the complete dependency chain through registration. Added LF rules for reproducible checkouts.
* Added an image/run identity guard before importing the inference build into k3s, and a
  separate baseline MLflow experiment for real comparison across distinct experiment IDs.
* Refreshed the DVC lock through an actual complete pipeline execution and updated documentation
  and exported evidence. No working integration was replaced.

  LLM scenario **passed** with actual `qwen2.5:1.5b`: six model turns, seven successful required

  The selected commit, pointer and MD5 match, and no trigger/restart was executed. Actual model

  [`llm-acceptance.json`](evidence/review-2026-11-15/llm-acceptance.json) and the full conversation;
  earlier failed attempts remain explicit.

`local-checks.json` distinguishes local execution from hosted GitHub Actions. The user confirmed
that only the first historical `feat:…` run failed and subsequent hosted runs passed. The public
repository API returned 404; SSH repository access was restored through the owner's login.
No historical run was deleted or rewritten. The final pushed commit still requires its own
hosted Actions result; SSH Git access does not provide authenticated Actions API access.
The repository owner explicitly chose to verify hosted CI; local passing checks are not
presented as a hosted result.

Manual checks: view the latest pushed commit's Actions run, ensure the evaluator has repository
access, and deliver the required oral demonstration/defense. A dated local snapshot does not
replace those checks or guarantee an evaluator's score.

## Reproduce this review

After following the README setup and launching MLflow, Airflow, Kubernetes, deployed inference,
and Ollama with the configured model:

```bash
uv run python -m scripts.verify_local
uv run python scripts/demo.py --planner rules --trigger --confirm-failures --output docs/evidence/review-2026-11-15
uv run python -m scripts.verify_live
OLLAMA_TIMEOUT_SECONDS=360 OLLAMA_MAX_SECONDS=1200 TOOL_TIMEOUT_SECONDS=45 uv run python scripts/demo.py --planner ollama --only-multi --output docs/evidence/review-2026-11-15/ollama
```

State-changing setup/fault-injection commands are explicit operator actions. The agent's
mandatory diagnostic request supplies no mutation confirmation. Token expiration and service
shutdown can invalidate a later live check; exported timestamps describe the tested snapshot.
